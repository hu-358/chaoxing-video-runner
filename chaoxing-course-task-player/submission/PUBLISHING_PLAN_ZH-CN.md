# Microsoft Edge 公开上架完整执行计划

适用版本：2.2.0
发布者显示名称：HuZaiming
首发市场：中国大陆
语言：简体中文
定价：永久免费、无广告、当前无捐赠功能
架构：扩展完全在用户本地运行，不使用开发者服务器

## 一、不可消除的风险边界

本扩展保留自动播放视频、浏览文档和切换后续任务的能力。即使不构造隐藏请求、不绕过验证码，并要求用户每次打开或刷新后主动点击开始，Microsoft 仍可能依据“自动化平台操作”、单一用途、误导性功能或其他政策拒绝上架。学习通、学校或课程规则也可能限制这类使用方式。

因此，本计划的目标是做到如实披露、最小权限、数据本地化、可测试和可追溯，而不是承诺必然通过审核或对所有使用场景给出法律保证。不得通过隐藏功能、模糊命名或虚假问卷答案降低审核可见性。

## 二、已经完成的发布整改

1. 升级到 Manifest V3 候选版本 2.2.0。
2. 页面范围限制为两个学习通 HTTPS 路径，移除 HTTP、宽泛门户脚本和显式 `host_permissions`。
3. 权限仅保留 `storage` 与 `notifications`。
4. 新增首次使用说明和明确确认；未确认时不运行、不读取课程状态，也不保存设置。
5. 每次课程页面重新打开或刷新后保持暂停，必须再次由用户点击“开始 / 继续”。
6. 不处理考试、测验、作业、讨论和问卷，不绕过验证码、人脸或身份验证。
7. 跨窗口消息只接受学习通 HTTPS 来源，并使用精确目标来源。
8. 本地清除功能覆盖当前课程和全部扩展数据；全部清除也撤销首次确认。
9. 桌面通知改为通用文案，不显示课程或任务名称。
10. 提供不联网、使用虚构内容的审核演示。
11. 补齐隐私政策、支持页、产品说明、许可证、商店文案、认证说明、素材和拒审处理流程。

## 三、正式提交的阶段与准入门槛

### 阶段 A：账号与身份

按照 `ACCOUNT_SETUP_ZH-CN.md` 注册个人开发者账号。Microsoft 验证资料必须真实；商店对外名称使用 HuZaiming。完成账号验证前，不提交包。

准入门槛：可以进入 Partner Center，新建 Edge 扩展并看到发布者名称 HuZaiming。

### 阶段 B：GitHub 与公开页面

1. 使用现有公开仓库 `https://github.com/hu-358/chaoxing-video-runner`。
2. 提交源码、许可证和文档；不要把真实账号、Cookie、课程信息、日志或密钥提交到仓库。
3. 将 `.github/workflows/deploy-pages.yml` 提交到主分支，并在仓库 Settings → Pages 中将 Source 设为 GitHub Actions；工作流会发布 `chaoxing-course-task-player/docs/`。
4. 在无登录浏览器窗口验证产品、隐私和支持页面。
5. 建立 `v2.2.0` 标签和同名 Release，附上 ZIP 与 SHA-256。

准入门槛：三个公开 URL 均返回正常页面，仓库当前标签与包内版本一致。

### 阶段 C：Edge Stable 手工验收

从 `edge://extensions/` 加载 `extension/`，使用本人有权访问的页面完成以下测试：

| 场景 | 预期结果 |
| --- | --- |
| 首次安装 | 自动打开说明页；未勾选时不能确认 |
| 未确认打开课程 | 面板提示确认；扩展不开始处理 |
| 主动开始 | 扫描任务并仅处理视频和官方文档 |
| 点击暂停 | 视频停止、运行锁释放、状态保存 |
| 页面刷新 | 不自动继续，明确提示再次点击开始 |
| 多标签同课程 | 同一时刻仅一个标签可运行 |
| 验证码/人脸/身份验证 | 自动处理暂停，等待用户本人操作 |
| 考试、作业、讨论、问卷 | 不处理 |
| 文档关闭 | 跳过文档任务且如实显示 |
| 清除当前课程 | 只移除当前课程状态与日志 |
| 清除全部数据 | 状态、设置和首次确认全部移除 |
| 离线审核演示 | 断网仍可打开，不产生真实记录 |

若学习通页面结构变化导致任何核心场景失败，先修复并提高版本号，不提交已知失效版本。

准入门槛：以上项目有本地测试记录，且截图中没有真实个人或课程数据。

### 阶段 D：生成不可变候选包

1. 运行 JavaScript 语法检查、自动测试和发布规则检查。
2. 运行 `scripts/build-edge-package.ps1`。
3. 核对 `manifest.json` 在 ZIP 根目录。
4. 记录 SHA-256，并确保此后不再修改 `extension/`；如修改，必须重建、重测并更新哈希。

准入门槛：所有检查通过，ZIP 哈希与 `release/SHA256SUMS.txt` 一致。

### 阶段 E：Partner Center 填写与提交

1. 上传 ZIP，选择 Public，可用市场先仅选 China。
2. 使用 `STORE_LISTING_ZH-CN.md`，分类优先选教育；无教育时选生产力。
3. 填入 GitHub Pages 的产品、隐私、支持 URL 和支持邮箱。
4. 按 `PRIVACY_AND_PERMISSIONS.md` 逐项填写权限与数据使用；不要选择“完全不访问数据”。
5. Remote code 选择 No；广告、应用内购买和成人内容均为 No。
6. 按 `ASSET_INVENTORY.md` 上传 Logo、推广图和功能截图。
7. 将 `CERTIFICATION_NOTES_ZH-CN.md` 粘贴给审核员，明确无可共享真实学校账号并提供离线演示路径。
8. 提交前保存每个表单页面的截图或导出副本，记录提交日期、版本与 ZIP 哈希。

准入门槛：商店描述、隐私政策、问卷答案和实际包行为四者完全一致。

## 四、审核期间

- 不在审核中的 2.2.0 包对应分支上混入功能变更。
- 保留提交包、哈希、文案、截图和提交时间。
- 若审核员索要说明，回答实际行为，不提供无权分享的学校账号。
- 如果需要新包，版本至少提高为 2.2.1，并重新完成全部测试与披露核对。

## 五、拒审处理

收到拒审后先保存原文、政策编号、截图、提交 ID 和包哈希，再按 `REJECTION_PLAYBOOK.md` 分类处理。

- 自动化或学术诚信：优先评估是否必须改成仅辅助、仅提示或逐任务人工触发；不要只改文案。
- 商标或关联性：保留指定非官方声明，并按要求调整名称、图标或关键词；不得暗示官方关系。
- 权限或隐私：以实际代码为准缩减权限，并同步更新政策、商店问卷和截图。
- 无法测试：增强离线演示与步骤；仍不提供无权共享的真实账号。
- 技术故障：修复后提高版本号并提供最短复现与验证步骤。

申诉只引用实际证据，例如具体文件、测试步骤和权限范围。若功能确实违反政策，应先整改而不是争辩措辞。

## 六、通过后的发布与维护

1. 记录商店 ID、公开 URL、批准日期和上线日期。
2. 从干净环境安装商店版，复测安装、首次确认、课程页暂停状态、清除数据和离线演示。
3. 在 GitHub Release 标记与商店一致的版本和哈希。
4. 只收集用户主动发送且已去除个人信息的问题报告；不要求密码、Cookie、学号或真实课程截图。
5. 每次更新都执行：需求界定 → 权限/数据差异审查 → 版本号提升 → 自动测试 → Edge 手测 → 隐私与商店文案同步 → 新包与哈希 → Partner Center 更新。
6. 若未来加入捐赠、服务器、遥测、广告、新网站范围或新数据类型，必须在编码前重新评估合规性，不得沿用当前披露直接上线。
